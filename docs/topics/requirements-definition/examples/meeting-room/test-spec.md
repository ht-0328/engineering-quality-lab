# 実例：テスト仕様書（抜粋）

架空の「会議室予約システム」のテスト仕様書から、予約の重なりに関する部分だけを抜き出したものです。

- テスト工程ごとに、「入力にした成果物」と「テスト項目」を書いています。
- 各テスト項目に、元になった記述の ID を「元」として書いています。
- 元の成果物：[要件定義書](requirements.md)、[設計書](design.md)

実行したかどうか：

- 単体テストと結合テストは、テストコードを書いて実行し、すべて成功しました。
- システムテストと受入テストは、仕様だけです。画面と API を実装していないため、実行していません。

## 単体テスト（部品1つを確かめる）

入力にした成果物：詳細設計 DD-01

- **UT-01**：一部が重なる時間帯は「重なる」と判定する（元：DD-01）
    - 10:00〜11:00 と 10:30〜11:30 → 重なる
- **UT-02**：終了と開始が同じ時刻の時間帯は「重ならない」と判定する（元：DD-01、BR-02）
    - 10:00〜11:00 と 11:00〜12:00 → 重ならない（順番を入れ替えても同じ）
- **UT-03**：片方がもう片方に含まれる時間帯は「重なる」と判定する（元：DD-01）
    - 10:00〜12:00 と 10:30〜11:00 → 重なる
- **UT-04**：離れた時間帯は「重ならない」と判定する（元：DD-01）
    - 10:00〜11:00 と 13:00〜14:00 → 重ならない

## 結合テスト（部品をつないで確かめる）

入力にした成果物：詳細設計 DD-02、基本設計 TBL-01

前提：会議室 A に 10:00〜11:00 の予約が1件ある。

- **IT-01**：重なる予約は登録されない（元：DD-02 手順4）
    - 会議室 A を 10:30〜11:30 で予約する → エラーになる。会議室 A の予約は1件のまま
- **IT-02**：別の会議室なら、同じ時間帯でも登録できる（元：DD-02 手順2）
    - 会議室 B を 10:00〜11:00 で予約する → 登録される
- **IT-03**：続きの時間帯は登録できる（元：DD-02 手順3、DD-01）
    - 会議室 A を 11:00〜12:00 で予約する → 登録される。会議室 A の予約は2件になる
- **IT-04**：終了日時が開始日時より後でない予約は登録されない（元：DD-02 手順1）
    - 会議室 A を 13:00〜13:00 で予約する → エラーになる

## システムテスト（システム全体が要件どおりに動くかを確かめる）

入力にした成果物：要件定義書 UC-01、基本設計 SCR-01

- **ST-01**：基本シナリオどおりに予約できる（元：UC-01 基本シナリオ）
    - 手順：ログインし、予約登録画面で、予約のない会議室と時間帯を入力して「予約する」を押す
    - 期待結果：登録した内容が表示される
- **ST-02**：時間帯が重なると、知らせが出て、登録されない（元：UC-01 例外シナリオ1、SCR-01）
    - 手順：予約のある会議室と、重なる時間帯を入力して「予約する」を押す
    - 期待結果：MSG-01 が表示される。予約は増えない。入力した内容は画面に残る
- **ST-03**：終了日時が開始日時より後でないと、知らせが出て、登録されない（元：UC-01 例外シナリオ2、SCR-01）
    - 期待結果：MSG-02 が表示される。予約は増えない

## 受入テスト（使う側が、業務で使えるかを確かめる）

入力にした成果物：要件定義書 R-01、BR-01、BR-02

- **UAT-01**：二重予約が起きない（元：R-01、BR-01）
    - 場面：総務の A さんが、会議室 A を 10:00〜11:00 で予約している。営業の B さんが、同じ部屋を 10:30〜11:30 で予約しようとする
    - 期待結果：B さんは予約できない。B さんは、時間か部屋を変えて予約し直せる
- **UAT-02**：会議を続けて入れられる（元：BR-02）
    - 場面：A さんの会議が 11:00 に終わる。B さんが、同じ部屋を 11:00〜12:00 で予約しようとする
    - 期待結果：B さんは予約できる
