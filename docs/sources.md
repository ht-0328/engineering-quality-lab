# 情報源台帳

調査で使う情報源と、**どこまで実際に読めたか**を記録します。全テーマ共通で1つの台帳です。

## 確認状況の意味

| 確認状況 | 意味 |
|---|---|
| 本文確認 | 本文を開いて、該当箇所を読んだ |
| 一部確認 | 抄録（論文の要約）・目次・公式の紹介ページだけを読んだ |
| 二次情報のみ | 他人の解説や検索結果の要約でしか見ていない |
| 未確認 | 開けていない。内容はAIの記憶にすぎない |

注意：ここでの「確認」は、AIがページを開いて読み取った結果です。人が原文を読んで確かめたものではありません。大事な判断に使う前に、原文を自分で確認してください。

## 個別の記録

### S01 Frattini ほか (2023)
- URL：https://arxiv.org/abs/2309.10355 （掲載誌：Requirements Engineering）
- 読んだ範囲：arXiv の抄録
- 確認できたこと：著者らは、要求品質の研究は「規範的なルール」（こう書くべき、という決まり）に集中しており、後の開発作業への影響とほとんど結び付けられていない、と述べている。
- 確認していないこと：本文の根拠、調査した文献の数、提案している理論の中身。
- 注意：著者の一部が S03 と重なる。1つの研究グループの見方であり、広く合意された見方かどうかは未確認。

### S02 Méndez Fernández ほか (2016)
- URL：https://arxiv.org/abs/1611.10288 （掲載誌：Empirical Software Engineering）
- 読んだ範囲：arXiv の抄録
- 確認できたこと：10か国・228社から得たデータを分析した実務者調査であること。要求に関する作業でどんな問題が起きているかを扱っていること。
- 確認していないこと：どの問題が多いかの順位、原因、影響。
