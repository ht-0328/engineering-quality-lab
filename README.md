# engineering-quality-lab

ソフトウェア開発で「良いものとは何か」「どうすれば良いと判断できるのか」を、調べて、比べて、試して、学ぶための個人プロジェクトです。

## 何のためのリポジトリか

AIに設計書を作らせたり、レビューや調査をさせたりすることはできます。しかし、その結果が良いのかどうかを自分で判断できなければ、仕事を任せきれません。

このリポジトリでは、AIの答えをそのまま正解にせず、根拠を確かめながら、自分で判断できる知識を少しずつ増やします。

## 基本の考え方

- AIの答えを正解として扱わない。情報源に書かれていることと、AIが考えたことを分ける。
- 「これが最善」と決めつけない。何が良いかは、目的や制約で変わる。
- 評価の基準そのものも疑う。項目が多いほど良いとは考えない。
- 調べるだけで終わらせず、可能なら架空のサンプルで試す。
- 完璧を求めない。何が確認できたら一旦終わりにするかを、先に決める。

## 対象

要求定義・要件定義、設計、実装、テスト、品質保証・レビュー、開発プロセス、AIを使った開発方法、技術的な意思決定など。一度に全部は扱わず、テーマを1つずつ進めます。

## 扱わないもの

- 職場の資料・コード・機密情報は置きません。検証には架空のサンプルを使います。
- 有償の規格や書籍の本文は、長く書き写しません。
